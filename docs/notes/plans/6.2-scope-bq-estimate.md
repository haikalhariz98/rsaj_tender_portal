## 0. Findings in today's code

- **No estimate exists anywhere.** `SourcingExercise.estimatedValue` is the exercise value: it bands the exercise and stays that. 6.11's "above estimate within approval" warning reads it, labelled "exercise value".
- **BQ today is a text field.** `bqReference` on the emergency coordination record (FR-REQ-013). It stays, and links to the BQ where one exists.
- **The closing date arrives with 6.4, not 6.5.** FR-DOC-012 records DATE START and CLOSING DATE at Approval for Tendering (6.4 plan, Q-2 there). `versionFaults`/`leadTime` take `closingAt: Date | null`, and null reads "Closing not set".
- **The audit trail and action state would leak the figure.** `writeAudit` stores before/after and History renders it. Sourcing actions return their faults to the form, so the estimate action must return codes only.
- **The document store exists** (`src/lib/documents`, ADR 0011). Owners are typed nullable FKs on `DocumentAttachment` with a `num_nonnulls` CHECK and `purposeFits`/`ownerState`. Uploads go through a Route Handler because of the 1 MB Server Action cap. SULIT files are listed and never downloadable before sign-in.
- **Not used by 6.2:** the decided-step builder (`authority/decided-step.ts`) and R3 core routing. 6.2 opens no approval route. Scope approval is a committee decision read through `decisionRecord()`. Panel verifications are attestations, not route steps.
- **The exercise page is 1,209 lines with seven tabs** (classification, contract, proposal, name, award, access, history). New tabs live in their own files under `src/app/sourcing/[id]/scope/`.
- **Spec conflicts carried to RSAJ:** FR-EST-010 says the company estimate; FR-OPN (l.1712) says the department estimate (OD-8).

## 3. Pure functions: `src/lib/scope/**`, vitest beside each

1. `bq.ts`: `itemAmount(qty: string|null, rate: Sen|null): Sen|null` wraps `lineAmount` (qty to 3 places × sen, half up). `bqTotals(items, excludeProvisional: boolean|null): BqTotals` returns `{ measuredFirm, provisionalQuantities, primeCostSums, provisionalSums, total, buildersWorks, firmValue: Sen|null, provisionalSharePct: string }`. `finaliseFaults(v, { policy, qualifications, today })` covers NO_ITEMS, ITEM_INCOMPLETE, STANDARD_NOT_SET, STANDARD_UNANSWERED, DEPARTURES_REQUIRED, QUALIFICATION_NOT_SET, PREPARER_NOT_QUALIFIED, TIME_ZONE_NOT_SET. `reviseFaults(v, exerciseStatus)` refuses once 6.4 has the pack under approval. `unpricedBq(frozen)` (OD-8, for 6.4) strips rate, amount and totals.
2. `panel.ts`: `panelFaults(panel, columns, policy)` covers COLUMNS_NOT_SET, COLUMN_UNVERIFIED, OVER_SIGNATORY_LIMIT, LIMIT_NOT_SET (warn), KIND_NOT_SET, STATUS_NOT_SET, LISTS_NOT_SET.
3. `csv.ts` (inc 2): `parseBqCsv(text)` returns `{ rows, faults: {line, code}[], keyedMismatches: {line, keyed, computed}[] }`; `bqToCsv(frozen, { priced })`.
4. `rates.ts` (inc 2): `scheduleInForce(issues, day)`, `priceFromSchedule(item, issue)` (snapshot), `scheduleEditFault(issue)`.
5. `scope-matter.ts` (inc 2): `scopeApproval(method, decisions, bqVersion)` returns `"NOT_REQUIRED" | "APPROVED" | "PENDING" | "RULE_NOT_SET" | "COMMITTEE_NOT_SET"`. `scopeApprovalRequired == null` gives RULE_NOT_SET, never NOT_REQUIRED. `scopeTablingFault` covers not finalised, already cited, wrong committee.
6. `estimate.ts`: `versionFaults({ value, personId, reason }, est, { closingAt, timeZone, exerciseStatus, now })` covers NOT_POSITIVE, SECOND_PREPARER, REASON_REQUIRED, AFTER_CLOSING, DISCLOSED, VOID, EXERCISE_CANCELLED. `startFault(live)` gives LIVE_ESTIMATE_EXISTS. `voidFault(est, reason)` refuses after LODGED. `lodgeFaults`. `custodyList(policy, holders, preparerId, day)` and `viewFault(...)` are built for sign-in and imported by nothing in `src/app` (source-scan test). `leadTime(lastVersionDay, closingAt, policy, timeZone)` returns `{ state: "READY"|"LATE"|"LEAD_NOT_SET"|"CLOSING_NOT_SET"|"TIME_ZONE_NOT_SET"; lastPermittedDay? }`. `overrideFaults(person, policy, reason)` gives OVERRIDE_NOT_PERMITTED when the role is unset. `estimateView(est, sealedFigures | null)` returns `{ sealed: true }` until DISCLOSED. `disclose(est, at)`. `benchmarkRow(est, figures, policy)`. `againstBill(view, billTotal)` returns `{ sealed: true }` until disclosed. `actionResult(faults)` returns codes only.
   **Single accessor:** `src/lib/scope/estimate-store.ts` `readSealedFigures(tx, estimateId)` is the only code that sets `omit: { value: false, reason: false }`. `src/lib/db.ts` gains a global `omit: { companyEstimateVersion: { value: true, reason: true } }` (the generated Prisma 7 client supports it: `GlobalOmitConfig`).
7. `pack.ts`: `packFaults({ basis, method, bq, panel, estimate, scopeApproval })` covers BQ_NOT_FINALISED, BASIS_BQ_NOT_SET, PANEL_NOT_VERIFIED, ESTIMATE_NOT_LODGED, ESTIMATE_RULE_NOT_SET, plus inc 2 SCOPE_NOT_APPROVED and SCOPE_RULE_NOT_SET. Each fault names where to fix it.
8. `labels.ts`, `audit-view.ts`: every label. History maps estimate rows to "Sealed (version N)".

**Tests that fail if the rule is removed.** All money in sen. BQ worked example: SK011 §7.2.4 BWV and FR-EST-002.
1. 1,250.5 m × RM182.40 = RM228,091.20. 1.5 × RM0.03 = 5 sen (half up). A keyed amount that differs is reported and ignored.
2. BQ: preliminaries 1 × 45,000.00; pipe 228,091.20; excavation under road 310 m³ × 65.75 provisional = 20,382.50; PC sum 18,000.00; provisional sum 6,500.00. Total 317,973.70. Builders' works (§8.3: total − PC − PS) 293,473.70. Provisional share "6.4101". Firm value 297,591.20 when excluded, 317,973.70 when not, null when not stated.
3. FR-EST-002 note: 350,000.00 of 1,000,000.00 gives "35.0000". The 30% routing stays in 6.13's configured rows.
4. Finalising refuses an unset standard, an unanswered standard, "no" without departures, an unset qualification, and a qualification that lapsed the day before.
5. Lead 7, closing 2026-11-19 14:30 Asia/Kuala_Lumpur: last permitted 2026-11-12. A last version on 2026-11-12 is READY; on 2026-11-13 it is LATE. 2026-11-12T17:30Z is 13 November local, so LATE. Lead unset gives LEAD_NOT_SET, closing null gives CLOSING_NOT_SET, time zone null gives TIME_ZONE_NOT_SET.
6. A second Person amending gets SECOND_PREPARER. v2 without a reason is refused. Amending after `closingAt` or after DISCLOSED is refused. Voiding after LODGED is refused. Starting while a non-VOID estimate exists is refused. After voiding, a new preparer's v1 is accepted.
7. `estimateView`, `againstBill` and `benchmarkRow` return sealed while DRAFT or LODGED. After `disclose()`: 330,000.00 vs 317,973.70 gives +12,026.30, +3.7822%. The audit-view row for an amendment contains neither the value's digits nor the reason text. `actionResult` carries no value.
8. Source scans: only `estimate-store.ts` un-omits `value`/`reason`; `viewFault` is not imported under `src/app`; the literal 4,200,000 appears nowhere in `src/`.
9. Inc 2: superseding a schedule leaves a priced line unchanged. `scopeApproval` with the flag null gives RULE_NOT_SET. CSV round trip of example 2 (priced) gives identical totals; the unpriced export has no rate or amount column.
10. Classification: an attempt to set the estimate below SULIT is refused via `lowers()`.
