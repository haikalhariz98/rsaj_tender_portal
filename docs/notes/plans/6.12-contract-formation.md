## 2. Data model (additive, nullable or defaulted, `organisationId` on every new model; Decimal(18,2) money, Decimal(9,4) percentages)

### 2.2 Baseline
- `ContractBaseline` (org, contractId, `version Int`, `reason` CONFIRMED | EXECUTED | POSSESSION | CORRECTION, `correctionReason`,
  `recordedAt`, `@@unique([contractId, version])`). Columns, each with a `…Source` (APPENDIX | AWARD | BQ | ENTERED) where it can
  come from more than one place, and one `provenance`:
  `contractSum`, `contractDate?`, `possessionDate?`, `completionPeriod`, `completionUnit`, `dateForCompletion?` (derived),
  `dlpApplies Boolean?`, `dlpMonths?`, `ladKind?` + `ladAmount?` / `ladPct?` + `ladUnit` + `ladDaily?` (resolved against the contract
  sum, 6.4 Q-6), `retentionApplies Boolean?` (from the exercise's `bandSnapshot`, as `dlpApplies`; 6.11 BD-35 never stores "not
  asked" as zero), `retentionPercent?`, `retentionCapPercent?`, `pcSums?`, `provisionalSums?`, `buildersWorksValue?` (derived),
  `firstInterimMinimum?` (derived or Appendix), `subsequentInterimMinimum?`, `honourCertificateDays?`, `unfixedMaterialsPct?`,
  `onCostPct?`, `designWorkValue?`, `sectionalCompletion Boolean?`, `snapshot Json` (every policy value it was built under).
- `ContractSection` (org, baselineId, `ref`, description, ladKind/amount/pct, `ladDaily?`, sortOrder): copied per version.
- Corrections after a certificate has pinned a version need a reason and never rewrite that certificate (LESSONS snapshot rule).

## 4. Actions (`src/app/projects/[id]/formation/actions.ts`; re-run the lib check on locked rows; audit before/after in the same transaction; named Persons "recorded on behalf of, not signed")

**Canonical lock order for every post-award write (6.12, 6.13, 6.14):** Requisition → SourcingExercise → Award → Contract →
Certificate → domain row, each `SELECT … FOR UPDATE`, through one helper `withLockedContract` in `src/lib/contract/repo.ts` that
extends 6.11's `withLockedAward`. 6.11's register writes (`lodgeSecurity`, `reviewSecurity`, `lodgePolicy`, `reviewPolicy`) already
take requisition → exercise → award (`inAward`), so `signFaults` and FR-PAY-014 eligibility read the bond and policy registers,
`commitmentFault` and the readiness gate on rows a concurrent rejection cannot change mid-check. A source-scan test keeps every
contract write on `withLockedContract`.

Start preparation (NUMBER_ALLOCATED → IN_PREPARATION; builds baseline draft) · mark part / record alternative · record reconciliation and
amendment signatures · record each check and corrections · submit / decide legal review · attach resolution · record WC check ·
record contractor + witness signatures · **record RSAJ signature** (`signFaults` under the locks; writes `contractDate`, baseline
version EXECUTED, `executedSnapshot`, status EXECUTED) · record stamping (STAMPED) · issue / recall / reissue copies · custody moves ·
confirm baseline (version CONFIRMED; allowed from IN_PREPARATION once the FR-PAY-014 conditions hold, OD-2) · correct baseline
(reason) · integrity briefing. Cancelling an award after EXECUTED stays refused (6.11 BD-17).
