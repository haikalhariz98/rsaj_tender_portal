# 6.14 Certificate generation and the document tracking form (Phase 4e): plan

**Status: increment 1 accepted with carries (7b92b98); increment 2 built and presented for review (2026-10-04; decisions log "6.14 increment 2", BD-614-23..36).** Originally a draft for the product owner's go (2026-10-01), written against `174cc1e` on `build-all-modules`.
Spec: §6.14 (FR-CRT-001–012), Appendix C.2–C.3 (form inventory, signature order, distribution), §8 (computed fields), §12 B6, OQ-17,
§13.6 4e ("runs through 4a to 4d"), §13.10 (typo corrections can follow), ADR 0008 (issued instruments are frozen text snapshots).

**Scope mapping.** 6.14 = §13.6 **4e**: the certificate engine, the routing sheet, the template register and the `/documents`
register. It owns no certificate's content: each certificate's figures and rules are 6.13's. Because 4e "runs through 4a to 4d",
6.14 is built in two increments:

**Order: 6.12 → 6.14 increment 1 (certificate core) → 6.13 Part A → 6.14 increment 2 → 6.13 Part B** (same sentence in all three
plans): 6.13's first certificate is 4b's delegation letter.

- **Increment 1 (straight after 6.12):** the certificate core (§2.1), signature order, date from signature, distribution,
  computed-field overrides, the routing sheet projection, the template register's signature blocks and distribution lists. FR-CRT-001
  (part), 002–009.
- **Increment 2 (after 6.13 Phase 4 is accepted):** `/documents` register, printed-form fidelity metadata (page count, language label
  pairs, field bindings), missing templates B6 as mechanism, FR-CRT-010, 011, 012.

## 0. What exists today (grep at `174cc1e`)

- **Instrument generation exists for awards only** (ADR 0008): `DocumentTemplate` has `formCode`, `revisionDate`, `bilingual`,
  `bodyMs/En`, `primaryLanguage`, `bodyVersion`, `documentClassId`; `AwardDocument` freezes rendered text, template identity and
  fields at issue; `award/merge.ts` `renderTemplate` (6.4 step 2 moves it to `src/lib/templates/merge.ts`) with a whitelisted
  merge-field set per instrument. Nothing has a signature-block order or a distribution list as configuration.
- **Distribution:** `AwardDistribution` (per-award copies) and `DistributionRecipient` (config per award instrument kind). 6.12 adds
  `IssuedCopy` with a `contractId` owner and a one-owner CHECK, for controlled copies.
- **Routing:** `ApprovalInstance` / `ApprovalStep` (ADR 0005) are the generic DAL route, with `ApprovalStep.receivedOn` (6.11 R15),
  successors for resubmission (ADR 0009), and 6.11's read model `award/routing.ts` (`committeeBlock`, `approverBlock`,
  `receivedOnFault`) for the routing-sheet blocks (FR-CTE-014). `MatterKind` has CONTRACT and VARIATION, unused.
- **`/documents` is NotBuilt** and promises: Library (generated register, versions, controlled copies), Templates (certificates and
  routing sheets, to printed-form fidelity, MS/EN), Review queue (contractor submissions against a service level), Distribution.
  The prototype's Documents screen is the review queue of supplier submissions (tabs Review queue / All submissions / Requirements /
  Library). The doc-store screens list stored files per record and unfiled ones under Configuration › Documents.
- **Demo:** series `demo_n3` key `certificate` (`DEMO/CERT/{SERIAL}`), class `demo_dc2` certificate (SULIT, controlled copy),
  templates `demo_dt2` interim_cert, `demo_dt3` routing_sheet (no bodies). Capability `issue_certificate` (`demo_cap9`).

## 2. Data model (additive; `organisationId` on every new model)

### 2.1 Certificate core (increment 1) — the interface 6.13 builds on (same text in the 6.13 plan §0.2)

- `enum CertificateKind` (closed product vocabulary, BD-DS-4 precedent). **Increment 1 ships only 6.13 Part A's kinds:**
  DELEGATION_LETTER, DELEGATION_NOTICE, INTERIM_PAYMENT, ADVANCE_PAYMENT, LAD_WARNING, NON_COMPLETION, VARIATION_APPLICATION,
  SO_INSTRUCTION, VARIATION, SUM_ADJUSTMENT. 6.13 Part B adds, each in its own migration before use (X-6): EOT,
  CONTRACT_PERIOD_AGREEMENT, PARTIAL_OCCUPATION, PRACTICAL_COMPLETION, SCHEDULE_OF_DEFECTS, MAKING_GOOD_DEFECTS,
  TERMINATION_INTENT, TERMINATION, TERMINATED_FINAL, NOMINATION_LETTER, FINAL.
- `enum CertificateStatus` DRAFT, IN_ROUTING, SIGNING, ISSUED, VOID.
- `Certificate` (org, `contractId` Restrict, `kind`, `number` from series `certificate` at issue (unique per org), `sequence Int?`
  (the per-contract ordinal "interim certificate 3": allocated at issue under the contract lock, `@@unique([contractId, kind,
  sequence])`; a voided draft never had one, so voiding consumes nothing; FR-PAY-014 and FR-FIN-005 read it), `status`,
  `sectionId?` (sectional completion), `templateId?` + `templateRevision Json?` (pinned at first signature), `baselineId` (pinned
  `ContractBaseline` version, Restrict), `computedSnapshot Json?`, `certificateDate?`, `routingTypeId?`, `routingReceivedOn?`,
  `voidReason`, `issuedAt?`, `issueSnapshot Json?`). Domain records own their content and point here by `certificateId @unique`.
- `CertificateSignature` (certificateId, `blockOrder`, `blockKind` RECOMMENDING | AUTHORISING | CONTRACTOR | WITNESS | APPLICANT |
  SUPPORTING, `personId?` / `name`, `officeCode?` + label snapshot (the S.O. as resolved on that day, §7.2 "retain the historical
  holder"), `icMasked?`, `decision?` (e.g. DISOKONG / TIDAK DISOKONG with cap where the block carries one), `signedOn`, `recordedAt`,
  `refused Boolean` (contractor refusal, FR-VAR-022)).
- `CertificateOverride` (certificateId, `fieldKey`, `computed`, `overridden` (both Decimal or text), `justification`, personId, recordedAt).
- `CertificateDocument` (as `AwardDocument`: frozen rendered text, fields, template identity, language, version, frozenAt).
- `IssuedCopy` + `certificateId?` (6.12's table; CHECK rebuilt from the full owner list, X-6).
- `ApprovalInstance` + `certificateId?` (Restrict); `MatterKind` + CERTIFICATE in its own migration.

### 2.2 Template register and routing configuration
- `FormSignatureBlock` (templateId, `blockOrder`, `blockKind`, `labelEn/Ms`, `datesCertificate Boolean`, `officeRule` SO | SO_REP |
  RECOMMENDING_OFFICER | CONTRACTOR | WITNESS | NAMED_OFFICE + `officeCode?`, `delegable Boolean?` (null refuses signing on it)).
- `FormDistribution` (templateId, `recipientCode`, `labelEn/Ms`, `mandatory`, `ackRequired`, `condition` NONE | GUARANTOR_EXISTS |
  CONSULTANT_ENGAGED, `isOriginal`).
- `RoutingSheetType` (org, code, labelEn/Ms, `certificateKind?`, `templateId?` (the printed sheet), provenance) · `RoutingCheckDef`
  (typeId, `order`, `kind` CHECKED | VERIFIED | ENDORSED, `officeCode?`) · `RoutingTarget` (typeId, `pctMin?`, `pctMax?` (min, max],
  `targetDays Int`, provenance) · `RoutingCheck` (certificateId, `iteration`, defId, personId, `on`, `note`).
- Inc 2: `DocumentTemplate` + `pageCount?`, `FormField` (templateId, key, labelEn, labelMs, `bound Boolean`, `computedKey?`),
  `TextCorrection` (+ `TextCorrectionForm`, the forms it names), `Term` + `TermAlias` (BD-614-25: a code and a wording per language for `{{term:code}}`).

All of it ships empty. RSAJ's form inventory (Appendix C), ICC targets and distribution lists are a go-live seed and test fixtures.

## 3. Pure functions: `src/lib/certificate/**` (vitest beside each)

| File / function | Tests that fail if the rule is removed (spec examples in **bold**) |
|---|---|
| `signature.ts` `nextBlock(blocks, signed)`, `signFault(blocks, signed, block, actor, ctx)` | **The Recommending Officer always signs before the Superintending Officer; out of order refused (FR-CRT-004).** A block whose office rule is SO accepts only the S.O. resolved for that day; a delegate with instruction authority only is refused on a value block (FR-PAY-017, FR-VAR-021); `delegable` null refuses; contractor refusal recorded and does not block (only on kinds whose block allows it). |
| `date.ts` `certificateDate(blocks, signatures, tz)` | Date = day of the `datesCertificate` block's act; none signed → null, shown "set when signed"; correction never future. |
| `distribution.ts` `copiesFor(rows, contract)`, `distributionFaults(copies)` | **Interim/VO-663/CPC/CMGD style: original + four copies incl. the guarantor (FR-VAR-023, FR-CMP-009)**; guarantor row skipped when the contract has no live bond; mandatory undespatched → NOT_DISTRIBUTED; ack before despatch refused. |
| `override.ts` `applyOverrides(computed, overrides)`, `overrideFault` | No justification → refused; totals not overridable (TOTAL_NOT_OVERRIDABLE); the snapshot keeps both figures. |
| `routing-sheet.ts` `routingSheet(type, instances, checks, targets)`, `elapsedDays`, `targetFor(type, pct)` | **4 weeks for non-completion, practical completion and making good defects: DATE (1) 2026-09-01, DATE (2) 2026-09-29 → 28 days, met; 2026-09-30 → 1 day over. Quotation variation: 20.00% → 2 weeks, 20.01% → 6 weeks. Interim variant (i) 21 + 21 + 10 = 52 days; variant (ii) 21 + 5 + 15 = 41 days** (fixture rows, never seeded); a type whose printed total differs from the sum of its parts shows both (OQ-17); resubmission renders two iterations side by side; no target → NOT_SET. |
| `sequence.ts` `nextSequence(issued, kind)` | Third issued interim → 3; a voided draft leaves no gap; a second contract starts at 1. |
| `status.ts` `certificateTransition` | DRAFT → IN_ROUTING (routing type set) → SIGNING (route APPROVED, or kinds with no DAL route) → ISSUED (all blocks) → VOID only before ISSUED with a reason; an issued certificate is corrected only by a later certificate (6.13 rules). |
| `fields.ts` `boundFields`, `mergeFields(kind)` | Every bound field resolves from snapshot or baseline; unknown key refused on template save (ADR 0008). |
| Inc 2 `corrections.ts`, `terms.ts` | **"CERTICATE" → "CERTIFICATE" with form code and revision unchanged** (fixture list); empty list → text as written; alias search finds both **"Tempoh Liabiliti Kecacatan" / "Tempoh Tanggungan Kecacatan"**. |

## 4. Actions (shared by every certificate kind; the owning 6.13 module calls these helpers inside its own transaction)

`src/lib/certificate/write.ts` (server-only helpers), inside 6.12's `withLockedContract`, in the canonical order Requisition →
SourcingExercise → Award → Contract → Certificate → domain row (6.12 plan §4; 6.11's register writes already lock up to the award); re-run
`signFault` / `distributionFaults` / the kind's own faults on the locked rows; audit before/after in the same transaction; "recorded on
behalf of, not signed". Helpers: `openCertificate`, `recordRoutingReceived`, `recordCheck`, `recordSignature` (pins the template revision
on the first one; on the last, allocates the number via `issueReference` and the per-contract `sequence`, freezes `CertificateDocument`, sets ISSUED),
`overrideField`, `despatchCopy`, `acknowledgeCopy`, `voidCertificate`. DAL decisions stay the engine's (`personDecisionWrite`,
`committeeCitationWrite`).

## 5. Screens

- **Certificate drawer/page** (`/projects/[id]/certificates/[certId]`), one shell for every kind: `PageHeader` (kind label, number or
  "allocated on issue", status), tabs Figures (the kind's component, overrides marked), Signatures (blocks in order, next one enabled,
  others disabled with the reason), Routing sheet (checks, DAL steps, DATE (1)/(2), elapsed vs target, iterations), Distribution,
  Print (live with "Draft — not issued" before issue; frozen text and fidelity line after).

  revision, issued day, copies), Distribution (copies outstanding or unacknowledged), Routing sheets (open sheets with elapsed vs
  target). Review queue: a Callout naming 6.15 (contractor submissions) if 6.15 has not built it; a link if it has.
- **Configuration › Templates** drawer gains Signature blocks and Distribution; **Configuration › Routing sheets** (types, checks,
  targets). Siblings: award Instrument tab, Configuration › Documents; 1280/1440/390, text-snapshot diff.
