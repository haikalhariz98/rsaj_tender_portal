## 0. What the code says today (findings, against the built code)

- **`SourcingExercise` exists (6.3, ADR 0006)** with status DRAFT / DOCUMENTS_IN_PREPARATION / CANCELLED. An award hangs on an
  exercise in DOCUMENTS_IN_PREPARATION. The exercise already carries every snapshot the award needs, and the award reads them and
  never copies or re-derives them: `requisitionId`, `sourcingMethodCode`, `contractTypeCode`, `regime`, `appointmentRuleKey` /
  `appointmentState`, `termsBandKey` / `termsState`, `boundaryOperator` / `onBoundary` / `boundaryRuled`, `bandSnapshot` (terms
  band label and whether retention and defects liability apply, as they stood), `classificationSnapshot`, `dossierReference` and
  `justificationReasonCode`. `classificationLockedAt` exists, documented "set on award (6.11)", and nothing sets it yet; the
  evaluator already reads it (`evaluationContext` → `lockedAt`).
- **Writes lock the requisition, then the exercise** (`withLockedRequisitionForSourcing`). The award's writes take the same two
  locks in the same order and then the award's own row, so a sibling award's value sum and the write it guards see one state.
- **`ApprovalInstance` / `ApprovalStep` (ADR 0005)** are generic. 6.3 uses `exerciseId` for the name-approval route (domain
  `name_approval`). The appointment route is a second instance on the same exercise, domain `appointment`; nothing opens one yet.
  Steps are decided by a named Person through 6.1's `holdersFor` / `deciderFaults`, which already refuses a committee step
  (`COMMITTEE_STEP`). A committee step on a requisition is discharged only by citing a matter (`citeCommitteeDecision`,
  `committeeCitationFault`, `committeeStepFrom(decisionRecord())`).
- **`CommitteeDecision` has a typed `requisitionId` only.** `tableMatter` links a REQUISITION matter by reference; an EXERCISE
  matter is stored with `matterRef` and links to nothing. The demo's 6.10 matters `demo_d1`–`demo_d6` are manual matters (no
  record kind, no reference), so none names an invented reference or can be cited by the award flow.
- **`decisionRecord()`** (`src/lib/committee/record.ts`) is null while PENDING and otherwise the frozen outcome, sitting reference
  and date, and votes; it carries the committee's **name**. The committee is checked through `Meeting.committee.code`.
- **`commitmentFault(req, instance)`** (`src/lib/requisition/commitment.ts`) exists and is tested, naming the first pending step;
  nothing enforces it. **`dossierFault`** (`src/lib/method/justification.ts`) exists and never passes on evidence (no document
  storage); nothing enforces it.
- **`DocumentTemplate`** has code, form code, revision date and bilingual flag, **no body**. Nothing generates a document.
- **Numbering:** `issueReference(tx, org, key, on)` locks the series row. Demo series: `demo_n1` requisition, `demo_n2` contract
  (DEMO/KP/T/…), `demo_n3` certificate, `demo_n4` meeting, `demo_n5` exercise, `demo_n6` direct_appointment. The plan's first draft
  gave `demo_n6` to awards; it is taken, so awards use `demo_n7`.
- **Code formats:** `demo_f1`–`demo_f4` exist; `erp_indent_no` is `demo_f5`.
- **Demo authority:** tender appointments route to the Tender Board (committee step, act A); quotation appointments route to
  the Quotation Committee (MR) then the Chief Executive (A). `QUOTE_CTTE` (`demo_c2`) has quorum and voting rule unset on purpose
  (6.10) and two voting seats (FD chair, `demo_p4`). Demo rule ids 10–19 are free.
- **Money / dates:** Decimal in the database; `Sen` (bigint) in `src/lib` via `parseSen`; days through `todayIn` / `dayToDate` /
  `storedDay`; display through `formatMoney` and `formatOrgDay`.
- `NotificationRule` (eventKey + `reminderOffsetDays`) exists and sends nothing. There is no delivery infrastructure.
- The prototype's award tab has one unconditional "Issue the award" button and "{n}% of the accepted value" for the bond (a
  hard-coded basis, contrary to D4); neither is reproduced.

## 2. Data model (one additive migration `award`, after `proposal_record_route_order`)

ENV.md: `pmig.mjs create award`, no `;` inside a comment or string in the SQL, `verify.sh` ends with the empty migration, deploy leaves
no unfinished rows. Money `Decimal(18,2)`, percentages `Decimal(9,4)`. Every config table has `organisationId`, `provenance
@default(ASSUMED)`, `notes`, `sortOrder` and `retiredOn?`, and `@@unique([organisationId, code])` where it has a code. **The seed ships
zero rows in every new table.** Snapshot columns are new and null on existing rows; nothing is backfilled from configuration.

## 4. Generating the instrument without a document engine (ADR 0008)

- Template body is configuration: `DocumentTemplate.bodyMs` / `bodyEn`, `primaryLanguage`, `bodyVersion` (bumped on every audited
  body edit). Plain text with whitelisted `{{field}}` merge fields; rendered through React text nodes. Ships empty: an unset body reads
  "Template text not configured" and issue refuses.
- Which template: LoA, declaration and covering memo from `AwardPolicy` (BD-7); the appointment letter from the selected variant.
- Before issue `/awards/[id]/print/[kind]` renders live with a **"Draft — not issued"** watermark; on issue each document is frozen into
  `AwardDocument`, and the print route renders only the snapshot. The issued print carries the reference, version, form code and
  revision, `frozenAt`, and a fidelity caveat ("the portal's text of the issued instrument, not the controlled form"), no watermark.
- Indent: the Inden Kerja is the finance system's document; we record its number and receipt and generate the covering memo and the
  Pemberitahuan Perlantikan.
- Façade (INT-04/05): `src/lib/integration/award-commitment.ts` `CommitmentGateway`; the only adapter, `manualCommitment`, validates
  the typed number. `/awards` "Issued, no commitment number" is the INT-05 reconciliation list.
- Deferred: form fidelity, paging, bilingual label pairs (4e); PDF, e-signature, attaching returns (document storage); sending copies.
