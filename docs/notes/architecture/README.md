# Architecture decisions

One file per decision, numbered and never renumbered: `0001-short-title.md`.

Record a decision here when it constrains work that comes later — a boundary between
modules, a contract with an outside system, a choice between two designs that a future
reader would otherwise reopen. Do not record what the code already says plainly.

Each file states:

- **Context** — what forced a decision, and what was true at the time
- **Decision** — what was chosen, in the present tense
- **Consequences** — what this makes easy, what it makes hard, and what it rules out
- **Status** — proposed, accepted, or superseded by `NNNN`

A decision is never edited once accepted. If it turns out wrong, write a new one that
supersedes it and say why. The trail of reasoning is the point; a tidy record that hides
a reversal is worth less than an untidy one that explains it.
